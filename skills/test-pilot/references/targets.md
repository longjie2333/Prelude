# 各类目标的起点

接收阶段判断出目标类型后读对应的一节。这里只写起点：怎么驱动目标、证据是什么、哪些事最容易做错。类别经验（知识库里的 `SKILL.md`）比这里更具体，有就优先用。

## 网站 / UI

- **驱动**：优先用用户已配置的浏览器自动化 MCP；没有就写 Playwright 脚本。在**项目根目录**执行 `npm install playwright`（首次安装需要批准），复验时的复现脚本才找得到它；浏览器先试本机缓存，缺了再 `npx playwright install chromium`。不要用 curl 判断页面行为，前端逻辑跑在浏览器里；接口层面的问题可以用 `fetch` 单独确认。
- **复现脚本里的浏览器**：用 headless 模式，设置超时，`try/finally` 里关闭浏览器；连不上目标、登录失败时以 0 退出（未能证明问题）。
- **复现脚本**：Playwright 脚本本身就是复现脚本：断言失败时 `process.exit(1)`，并把截图、页面 HTML、控制台日志写到 `.prelude/work/` 作为证据。
- **证据**：每个 UI 发现至少一张截图；涉及前后端不一致时同时保存网络请求和响应。
- **体验问题**记为 `suggestion`：写清在哪个页面、哪个元素、什么问题、为什么影响用户、建议怎么改，附截图。
- 盲区清单里网站特别要看：表单校验前后端是否一致、重复提交、浏览器后退/刷新后的状态、键盘可达与焦点顺序、窄屏布局、错误页。

## 安全

- **授权**：只有 `scope.json` 中该目标的 `allowed` 含 `security-check` 才能做安全测试。没有就不做，记入"没测什么"；不要用别的方式绕过。授权只能由用户在 `scope.json` 里写，弹窗批准主机不会授予它。
- **扫描器**（ZAP、nuclei、sqlmap、ffuf 等）命令里必须写出目标 URL 或 `host:port`，闸门据此检查授权。
- **扫描器的原始结果不是缺陷**。每一条都要手工确认，写成复现脚本：脚本发出具体请求，断言具体的越权或泄露（例如"用户 A 的 token 读到了用户 B 的订单"），退出码非 0 才算复现。只有扫描器告警、没有复现脚本的，最多记在报告"测了什么"里。
- 优先看：越权（换 id、换角色、去掉 token）、注入（参数、头、JSON 字段）、敏感信息泄露（错误详情、调试接口、响应里的多余字段）、认证与会话（过期、重放、并发登录）。
- 强度：遵守 `scope.json` 的限制；不做拒绝服务类测试。

## 安卓 apk

- **环境**：需要模拟器或测试机和 `adb`。接收阶段确认设备（`adb devices` 的序列号）、安装方式、测试账号、后端环境。没有设备就不要在本机装模拟器以外的东西，直接问。
- **安装**：`adb -s <序列号> install -r <apk>`。这是装在设备上，闸门允许；在本机运行安装程序会被拦截。
- **驱动**：`adb shell am start`、`adb shell input`、`uiautomator dump` 读控件树；有 Appium/Maestro 等 MCP 或工具就用它们。
- **证据**：`adb exec-out screencap -p > shot.png`、`adb logcat -d` 中与应用相关的部分、控件树 XML。
- **复现脚本**：用 Node 或 Python 通过 `adb` 驱动并断言（读控件树或 logcat），退出码非 0 = 复现。脚本里写死设备序列号或从环境变量读。
- 特别要看：旋转屏幕与切后台后的状态、权限拒绝后的行为、弱网和断网、返回键、深链接、多语言与大字体。

## Windows 桌面程序

- **隔离**：被测程序只在 Windows Sandbox 或虚拟机里安装和运行。闸门会拦截在本机运行安装包（`msiexec`、`*.msi`、`setup*.exe`、静默安装参数）。接收阶段确认隔离环境在哪、怎么把安装包放进去、怎么执行命令；没有隔离环境就停在"测了什么：无"，不要在本机装。
- **驱动**：在隔离环境里用控件自动化（pywinauto 类）；覆盖不到的界面用截图加视觉判断，并在报告里写明哪些结论来自截图。
- **范围**：这一类允许只做到"能安装、启动并完成冒烟测试"，报告里写清楚没覆盖什么。
- **证据**：截图、程序日志、事件查看器中的崩溃记录、安装日志。

## CLI

- **驱动**：直接运行；用临时目录做工作目录，避免污染项目。
- **复现脚本**：用 Node 的 `child_process` 或 Python 的 `subprocess` 运行被测命令，断言退出码、stdout/stderr 和产生的文件。
- 特别要看：参数边界与组合、非法输入的退出码和提示、路径中的空格与非 ASCII 字符、管道与重定向、信号中断后的残留文件。
