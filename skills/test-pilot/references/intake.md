# 接收问题模板

先自己从目标拿能拿到的信息，只问拿不到的。所有问题放进**一次** `questionnaire` 调用，给出选项和合理的默认值，让用户能很快答完。

## 所有目标都要确认

- **环境**：测试的是哪个环境？是否是生产环境？（生产环境默认只读）
- **允许的操作**：可以写入数据吗？可以做负载测试吗（强度上限）？可以做破坏性操作吗（删除、重置）？
- **安全测试**：是否授权安全测试（扫描、注入、越权尝试）？
- **账号**：测试账号和角色（普通用户、管理员、只读等）。
- **数据**：如何重置或准备测试数据？有没有不能动的数据？
- **方向**：有没有重点关注的功能或已知问题？有没有不需要测的部分？

## 接口 / 服务

- 接口文档在哪里（OpenAPI、Postman 集合、源码）？
- 鉴权方式（token、cookie、签名），如何获取？
- 有无频率限制、幂等键、回调或异步处理？

## 网站

- 入口 URL、需要登录的页面、测试账号。
- 支持的浏览器和屏幕尺寸。
- 是否可以用浏览器自动化（已配置的 MCP 或 Playwright）？
- 是否需要关注可访问性、文案、国际化？

## 安卓 apk

- 设备或模拟器（型号、系统版本），adb 是否可用？
- 安装方式（apk 文件路径、应用商店测试轨道），是否需要先卸载旧版本？
- 测试账号、需要的权限（定位、相机、通知）、后端环境。

## Windows 程序（exe）

- 隔离环境：Windows Sandbox 或虚拟机在哪里？**不在用户主机上直接安装。**
- 安装包路径和版本，静默安装参数。
- 是否可以用控件自动化（pywinauto 类）？
- 重点功能和冒烟路径。

## CLI

- 安装方式和版本，支持的平台。
- 输入样例、配置文件、环境变量。
- 预期的退出码和输出格式约定。
