# 报告模板

写到 `.prelude/reports/<YYYY-MM-DD>-<主题>.md`。下面的二级标题都必须有（`report_finalize` 会检查）；某节没有内容就写"无"。发现用 `finding_record` 给出的 id（`f-001`）引用，每个 id 放在和复验结论一致的小节里。

```markdown
# <目标> 测试报告

## 结论

两三句话：测了什么系统、发现了几个已复验缺陷、最严重的是什么、整体判断。列出主要假设（接收阶段没问到、自己决定的事）。

## 已复验缺陷

只放复验结论为 confirmed 的缺陷，按严重程度排序。

### f-001 <标题>（high）

- 现象：实际发生了什么。
- 预期：应该怎样，以及依据（文档、契约、不变量）。
- 复现步骤：简短步骤；复现脚本 `<脚本路径>`。
- 证据：`<证据路径>`。
- 复验：复现 3/3；审查结论与理由。

## 建议

复验结论为 confirmed 的 suggestion：在哪里、什么问题、为什么影响用户、建议怎么改。

## 未复现项

复验结论为 not-reproduced 或 rejected 的发现，各写一句原因。

## 测了什么

覆盖的功能、接口、盲区清单中的项目，以及用的方法和工具。

## 没测什么

没覆盖的部分和原因：不在授权范围、用户拒绝、不适用、时间不够、缺少环境或账号。

## 隔离级别

本次测试的隔离方式。Windows 上写明"仅工具层策略，不是安全边界"。
```
